Page loads at 1366x768 sum up to 0.219 of layout shift not caused by input; 0.1 is the usual
"good" bound. The same page differs between runs and themes (`docs/golden-path`: 0.094 dark, 0
light), so part of it is timing: the gate injects the pinned font at `DOMContentLoaded` and the
site hydrates after first paint. Not in the R-01 change set: the cause is not yet known, and the
skill's three-strike rule asks for a diagnosis before a change. R-02: record the shift sources
(`LayoutShift.sources`) per load, with and without the pinned font, then decide.

After R-01: `site:all` 0.219 → 0.191, `docs/install` 0.089 → 0.066, but `docs/plugins/aep`
0.117 → 0.134 (light load), past the 0.01 tolerance. The before value ran on the page text of
7d184a1, the after value on dfc04b0, where pull request #110 rewrote that page; the mid build
(UXF-001 and UXF-005 only, dfc04b0 text) measured 0.134 too. Which of the two moved it is not
separated. `layout_shift.per_load` enters `ux/baseline.json` for the first time in R-01, at the
after values; the ratchet compares it in a round (`node ux/ratchet.ts --round`).
