# UXF-002: No search in the navbar

- id: UXF-002
- title: No search in the navbar
- class: affordance
- severity: S2
- metric: always_visible.hidden
- status: open
- found_by: R-01 gates (always-visible elements, skill § 4 gate 2)
- evidence_recording: none (no recorded sessions this round)
- evidence_screenshot: ux/rounds/R-01/shots/before-docs_install@1366x768-light.png
- evidence_lines: ux/rounds/R-01/report-before.md, every page: `always-visible: top: search: missing`
- regression_asset: ux/gates.spec.ts (always-visible `search`, held open by the adapter's `KNOWN_PROBLEMS` entry UXF-002)
- cost: S
- decision: R-01 D1

The site has no search. A reader who knows the command or skill name has to find it through the
sidebar or the navbar links; the skill's docs-site adapter holds search always visible.

Fix: a local search plugin, `@easyops-cn/docusaurus-search-local` 0.55.3 as the slot docs site
uses, in `docusaurus.config.ts` and `package.json`. Not taken in R-01: adding the dependency was
refused by this session's permission check, so it waits for D1 (`ux/rounds/R-01/decision.md`).
The change that adds it removes the UXF-002 entry from `KNOWN_PROBLEMS`; the gate then fails on a
page without search.

Caveat: the public site at beyond10x.github.io/docs/agentplugins/ is rendered by the Website
repository with the shared docs-system, which owns search there. This finding is about the
repository's own build (`task site-build`, local preview).
