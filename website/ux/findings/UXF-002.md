# UXF-002: No search in the navbar

- id: UXF-002
- title: No search in the navbar
- class: affordance
- severity: S2
- metric: always_visible.hidden
- status: closed
- found_by: R-01 gates (always-visible elements, skill § 4 gate 2)
- evidence_recording: none (no recorded sessions this round)
- evidence_screenshot: ux/rounds/R-01/shots/before-docs_install@1366x768-light.png
- evidence_lines: ux/rounds/R-01/report-before.md, every page: `always-visible: top: search: missing`
- regression_asset: ux/search.spec.ts (and the always-visible `search` gate in ux/gates.spec.ts)
- cost: S
- decision: R-01 D1, answered yes

The site had no search. A reader who knows the command or skill name had to find it through the
sidebar or the navbar links; the skill's docs-site adapter holds search always visible.

Fix: the local search plugin `@easyops-cn/docusaurus-search-local` 0.55.3, pinned exactly in
`website/package.json`, configured in `website/docusaurus.config.ts` as the slot docs site does
(hashed index of the docs, English). The UXF-002 entry of the adapter's `KNOWN_PROBLEMS` is gone, so
the gate fails on any page without a search box in view at the top and at the end of the content.

Red before, green after: `ux/search.spec.ts` (the box is fully in view at 1366x768 and 1280x720, and
"worktree" offers the Worktree reference and opens it) fails against the build without the plugin
and passes with it.

Caveat: the public site at beyond10x.github.io/docs/agentplugins/ is rendered by the Website
repository with the shared docs-system, which owns search there. This fix is for the repository's
own build (`task site-build`, local preview).
