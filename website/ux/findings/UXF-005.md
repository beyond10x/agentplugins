# UXF-005: Links in running text are told from the text by colour alone

- id: UXF-005
- title: Links in running text are told from the text by colour alone
- class: affordance
- severity: S2
- metric: axe.serious
- status: closed
- found_by: R-01 gates (axe-core `link-in-text-block`), after the UXF-001 fix
- evidence_recording: none (no recorded sessions this round)
- evidence_screenshot: none
- evidence_lines: R-01 measurement of the UXF-001 build: 52 page loads with `axe: link-in-text-block` (every docs page with a link in a paragraph or list item, both themes)
- regression_asset: ux/brand.spec.ts (and the axe-core gate in ux/gates.spec.ts)
- cost: S

With the site's purple applied (UXF-001), a link inside a paragraph differs from the body text by
less than 3:1 and has no underline (Infima sets `--ifm-link-decoration: none`), so a reader who
does not see the colour difference cannot find it. Before UXF-001 the blue differed enough from the
text; the fix of UXF-001 exposed this one, so both go in the same change.

Fix: `src/css/custom.css` underlines links in paragraphs, list items, table cells and quotes of
`.markdown` (not the heading anchors).

Red before, green after: the underline check in `ux/brand.spec.ts` fails against the before-build
and passes against the fixed build; the axe-core gate fails on the UXF-001-only build and passes
after.
